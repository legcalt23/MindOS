# MindOS iOS app

This directory hosts the iOS shell for the Compose Multiplatform tree produced
by the `:shared` Kotlin Multiplatform module.

**Current release status:** iOS is intentionally blocked from production. The
shared entrypoint renders a blocked screen and does **not** mount `App()` with a
preview session. Do not submit an App Store build until Firebase Auth, App
Check, Storage, Functions, Crashlytics and the release workflow are wired and
validated on macOS.

The Xcode project file (`iosApp.xcodeproj`) is **not committed**: it contains
machine-specific UUIDs and is generated from the surrounding files the first
time the project is opened on macOS. Everything else in this directory is the
source of truth.

> **Important**: This module only builds on macOS with Xcode installed.
> The shared Kotlin Multiplatform module skips the iOS targets on Windows /
> Linux (see `if (isMacOs)` in `shared/build.gradle.kts`) so the Android and
> desktop builds remain unaffected on those hosts.

---

## Prerequisites (one-time, macOS)

1. macOS 13+ with Xcode 15+ installed (`xcode-select --install`).
2. Homebrew → `brew install cocoapods` (or `sudo gem install cocoapods`).
3. JDK 17 (the same one Android uses).
4. Kotlin Multiplatform plugin for Xcode is **not required** — we use CocoaPods.

## First-time setup

From the repo root on a Mac:

```bash
cd iosApp
pod install
open iosApp.xcworkspace
```

`pod install` triggers Gradle (`./gradlew :shared:podInstall`) which produces
the `Shared.framework` binary and stitches it into the Pods project. Always
open the **`.xcworkspace`** generated by CocoaPods, never the `.xcodeproj`
directly — the workspace is what wires the shared framework in.

When iOS re-enters release scope, commit `Podfile.lock` and switch CI to
`pod install --deployment` so Firebase pod drift is reproducible. `Podfile.lock`
is not generated in this Windows environment.

When Xcode opens the workspace the first time, you'll need to:

1. Set the **Bundle Identifier** to `com.mindos.app` on the `iosApp` target
   (it must match the Firebase iOS app registered in `mindos-8452f`).
2. Pick your **signing team** under Signing & Capabilities → Team.
3. Wire `shared/src/iosMain/resources/GoogleService-Info.plist` into the
   `iosApp` target's "Copy Bundle Resources" build phase. (CocoaPods already
   declares the plist as a pod resource via `extraSpecAttributes`, so this
   step may already be wired.)

## Build / run

```bash
# From iosApp/ on macOS:
xcodebuild -workspace iosApp.xcworkspace \
           -scheme iosApp \
           -configuration Debug \
           -destination 'platform=iOS Simulator,name=iPhone 15'
```

Or via Xcode UI: select the `iosApp` scheme, pick a simulator, hit ⌘R.

## Project layout

```
iosApp/
├── README.md                     # This file.
├── Podfile                       # CocoaPods spec — links shared + Firebase.
├── .gitignore                    # Excludes Pods/, *.xcworkspace, build/.
└── iosApp/
    ├── iOSApp.swift              # @main entry — hosts MainViewControllerKt.
    └── Info.plist                # Bundle metadata (HTTPS-only, dark theme).
```

The Xcode project gets generated by the KMM wizard or by running
`./gradlew :shared:cocoapodsGenerateDefXcodeproj` on first setup. Once
generated, store `iosApp.xcodeproj` outside `.gitignore` if your team's
workflow expects it tracked; otherwise leave it generated per-machine.

## Verification deferred to macOS

The scaffolding committed here cannot be compiled on Windows / Linux because
Kotlin Multiplatform's iOS targets and CocoaPods both require Xcode. The first
macOS contributor to open the project should:

1. Run `pod install` and confirm it succeeds without errors.
2. Open `iosApp.xcworkspace` and confirm the project builds with ⌘B.
3. Run on a simulator and confirm the iOS blocked screen renders.
4. Wire real Firebase iOS session/App Check before replacing the blocked screen
   with the app entrypoint.
5. Commit `Podfile.lock`; then use `pod install --deployment` in CI.
6. Commit `iosApp.xcodeproj/project.pbxproj` if the team agrees to track it.
