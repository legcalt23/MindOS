## 1. Governance rules

1. **IDs are permanent and never reused.** An ID maps to one invariant forever. Do not rename an
   existing ID onto a different problem. Legacy IDs with `P0`/`P1` embedded are preserved as-is and
   recorded as aliases in §6.
2. **No row is ever deleted.** History is append-only. Correcting a past mistake means adding a
   `CORRECTION` / `RETRACTION` event (§3), never editing the wrong entry away.
3. **Allowed states:** `OPEN`, `IN_PROGRESS`, `MITIGATED`, `BLOCKED`, `CLOSED`, `REOPENED`, `SUPERSEDED`.
4. **Severity ≠ state ≠ evidence.** They are three orthogonal columns. Severity does not appear in the
   ID (it can change). Severity is not downgraded without new evidence.
5. **Epistemic classification (separate axis):** `VERIFIED`, `CLAIMED_BY_CLAUDE`, `INFERRED`,
   `NOT_VERIFIED`, `CONTRADICTED`. A green targeted test is not `VERIFIED` of the whole system.
6. **`MITIGATED` ≠ `CLOSED`. `BLOCKED` ≠ `CLOSED`.** Do not swap `OPEN`→`BLOCKED` to dodge ownership.
7. **`SUPERSEDED` must point to the new ID** (§6). A `SUPERSEDED` without a destination is invalid.
8. **A closed finding can be reopened.** State changes preserve history.
9. **Closure hierarchy of evidence (§5):** narrative from Claude never substitutes for code, diff,
   discriminating test, log, or artifact. A review applies ONLY to the diff/hash it examined. A green
   test closes a regression only if it is discriminating (fails on the bug/mutation).
10. **Mandatory update every task** — implementations, mini-phases, one-line fixes, refactors, docs,
    tests, read-only reviews, research, diagnostics, migrations, prompt/governance changes, no-code
    tasks, blocked/cancelled/interrupted tasks, and subagent work. No task is `DONE`/`COMPLETE`/`APTO`/
    `CLOSED`/`VERIFIED`/frozen/ready-for-next-phase until §8's checklist passes.
11. **No new findings invented.** A task with no new finding records a `NO_NEW_FINDINGS` checkpoint (§4)
    naming the scope reviewed, evidence inspected, and prior findings potentially affected.
12. **Single writer.** The primary session owns writes; subagents propose, the owner reconciles.
13. **Never store secrets or personal data** in this ledger (no credentials, tokens, cognitive payloads,
    cleartext PII, or un-minimized user identifiers).
14. **Targeted ≠ full integration.** A subset test run is `REPORTED_GREEN`, not `TEST_VERIFIED`. Only a
    full suite green over a frozen hash, with diff+XML+logs attached, is `TEST_VERIFIED`.
15. **Implementation ≠ mitigation ≠ closure.** Landing code is `CLAIMED_BY_CLAUDE`; reducing risk is
    `MITIGATED`; closing requires the finding's closure gate satisfied with evidence (§5).

## 5. Closure evidence requirements

A finding may move to `CLOSED` only when ALL of:

- an identifiable correction exists;
- a discriminating test exists where applicable (fails on the regression or an equivalent mutation);
- the command AND output are attached;
- the verified platforms are named;
- code, tests, docs, and this ledger agree;
- the final reviewer examined the SAME diff/hash;
- no known caller or bypass remains;
- the finding's closure gate (§2 column) is satisfied.

If anything is missing, it stays `OPEN`, `MITIGATED`, or `BLOCKED`.

### Hash convention (self-excluding)

The **Canonical SHA-256** in §0 is computed over the entire file **with the single line matching
`^Canonical SHA-256`** removed. To verify from the repo root:

```bash
grep -v '^Canonical SHA-256' MINDBOOST_AUDIT_LEDGER.md | sha256sum
```

The 64-hex output must equal the value stamped in §0. A lightweight validator lives at
[`scripts/validate-audit-ledger.mjs`](scripts/validate-audit-ledger.mjs) (unique IDs, valid states,
`CLOSED`⇒evidence+gate, `SUPERSEDED`⇒destination, 64-hex hash present & matching, no obvious secrets,
a checkpoint exists). Run: `node scripts/validate-audit-ledger.mjs`.

**This is a self-consistency checksum, not a tamper-resistant one.** The same writer recomputes and
re-stamps it, so it catches ACCIDENTAL divergence (concurrent writes, a forgotten recompute), NOT an
adversarial edit that also updates the stamp. Real tamper-resistance needs an EXTERNAL anchor — a signed
git commit/tag or a CI-published hash (`MB-LEDGER-0003`). Because single-writer is not mechanically
enforced (`MB-LEDGER-0001`), the §0 count+hash MUST be reconciled LAST (after all row appends) and
re-validated by re-reading the file before the task is declared done.
